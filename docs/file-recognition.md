# Bounded file recognition

A FileResponse means the response uses a declared success status/media type and passes the supported structural recognizer. Bytes are returned unchanged. It does not certify fiscal validity, rendering or general format conformance.

PDF support covers physical classic-xref files, at most32 revisions,100,000 object identities/physical objects,500,000 parsed values and64 levels. Xref entries must identify real lexical object headers, with matching generations. The root must be a Catalog with a coherent Pages tree, Parent/Count links, four-number MediaBox and a direct or resolved Resources dictionary. Strings, comments and stream payloads do not create objects. Stream lengths are bounded and can be a direct integer or a resolved integer object. Xref/object streams and linearized documents are outside this profile. Standard V1/R2 encryption dictionaries produce protected_pdf after the structural graph checks; bytes are not decrypted or rendered. Other unsupported protection profiles are refused.

ZIP support compares local and central metadata, CRCs, sizes and descriptors, including ZIP64; duplicate names and overlapping physical entries fail. At most10,000 entries and128MiB aggregate declared expansion are accepted. XLSX also applies64MiB per-part, case-distinct path collision, namespace/content-type/relationship-parent/internal-target and worksheet identity checks. Numeric sheetId values use positive unsigned32-bit identity, so1 and01 collide. Used sheets require separate worksheet parts and unique names/relationship IDs. Unused relationship aliases to an existing part are allowed. Each physical member inflates once; subsequent XML/graph reads reuse its bytes rather than re-inflating a target. XML forbids DTDs/entities and bounds depth64, attributes4096 per element, attribute value65536 characters and500,000 package elements. Fiscal XML has the existing100,000 element bound.

Inspection checks the documented Cancel object and total call deadline before returning success and between bounded parsing steps. Synchronous XML/native parsing steps do not promise a hard realtime interruption. The local catalog retains explicit limitations for inspection-time cancellation/deadline proof, saturated connect, native held resolver and arbitrary signal/task semantics; broad inflation/resource-exhaustion experiments are not claimed.

The PDF and OPC graph design is adapted from read-only Webmania Rust alpha5/6 src/pdf.rs and src/xlsx.rs in this program. The implementation and every executed qualification use Perl with its pinned native modules. Canonical fixture hashes and independently authored catalog49 data are attributed in t/fixtures/PROVENANCE.md and the external execution dossier.
